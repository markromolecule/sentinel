# Scale Concurrent Exam Traffic, Polling Elimination, and Infrastructure Sizing Context Specification

## 1. Overview & Objective

- **Problem Statement:** During live testing with 20–80 simultaneous students taking an exam, the **Instructor Monitoring Dashboard and Management Interface** experienced severe degradation: loading spinners hung, student status lists lagged or failed to render, action buttons were delayed, and live inspection views could not load reliably. In contrast, student clicks on the exam attempt page functioned locally, but the background traffic generated by student clients overwhelmed the backend server. When students finished the exam and exited, the instructor dashboard immediately recovered and became fast and responsive again.
- **Root Cause & Comprehensive Codebase Audit Findings:**
  A deep codebase scan across all React Query hooks, background intervals, and services revealed **5 compounding traffic leaks** generated by active student clients that flooded the backend during exams:
  1. **[Critical] Live Inspection 500ms Student Polling Loop:** In [`packages/hooks/src/live-inspection/use-student-live-inspection-publisher.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/live-inspection/use-student-live-inspection-publisher.ts), an unconditional 500ms timer repeatedly called `POST /api/live-inspections/directive` 2 times per second per student (**160 req/sec** for 80 students, **320 DB queries/sec**).
  2. **[High] Active Attempt Session Status 2,000ms Polling:** In [`packages/hooks/src/query/exams/use-exam-session-status-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-session-status-query.ts), `useActiveAttemptLifecycle` polled `GET /examination/flow/sessions/:id/status` every 2 seconds with `refetchIntervalInBackground: true` (**40 req/sec** for 80 students).
  3. **[High] Student Lobby Redundant Polling:** In [`use-exam-lobby-admission-status-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-lobby-admission-status-query.ts) (2.5s) and [`use-exam-lobby-count-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-lobby-count-query.ts) (5s), students waiting in the lobby generated **48 req/sec** despite `useLobbyRealtime` already delivering instant updates via Supabase Realtime WebSocket.
  4. **[Medium] Instructor Monitoring 2,000ms Polling:** In [`use-exam-monitoring-overview-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-monitoring-overview-query.ts) (2s) and [`use-exam-incidents-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-incidents-query.ts) (2s), heavy multi-table JOINs ran every 2 seconds.
  5. **[Database Bottleneck] Connection Pool Defaulted to 5:** In [`packages/db/src/db.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/db/src/db.ts), `DB_POOL_MAX` defaulted to `5` connections.
- **Why the Instructor Experienced the Freeze:**
  When 80 students were connected, their combined background polling pelted the single-container backend with **~200–250 HTTP requests/sec** and **~400 DB queries/sec**. Because the database connection pool had only 5 slots, all of the instructor's requests (`GET /examination/monitoring/:id`, student detail queries, live feed requests) were queued behind hundreds of student polling requests. Instructor components rendered loading states or delayed click handlers because the backend API took 5–10 seconds to respond.
- **Business / User Value:** Ensure effortless, zero-latency monitoring and management for instructors overseeing 50–150+ concurrent students, with instantaneous dashboard updates, real-time WebRTC spot checks on demand, and minimal backend server load.
- **Measurable Success Criteria:**
  - 100% elimination of continuous background polling from student clients (**0 background HTTP req/sec** for live inspection).
  - Overall backend request load during an 80-student exam reduced by **> 96%** (from ~208 req/sec down to **~7–8 req/sec**).
  - Instructor dashboard, student list, incident feeds, and action dialogs render in `< 200ms`.
  - Real-time LiveKit proctor spot checks wake up the student within `< 1.0s` via Supabase Realtime broadcast signaling.
  - Zero database connection exhaustion errors under 150 concurrent students using Supabase Supavisor Transaction Pooler on port `6543`.
  - 2 load-balanced Railway replicas providing high availability with zero single-point-of-failure.

## 2. Requirements & User Stories

### User Stories / Scenarios

- *As an Instructor monitoring an exam of 150 students, I want the live monitoring dashboard, student list, and incident feed to load and update instantly without lag, timeouts, or hung spinners.*
- *As an Instructor, I want to initiate live video spot-checks on flagged students and see their camera stream within 1–2 seconds without flooding the server or impacting other users.*
- *As a Student taking an exam, I want my answer progress to save reliably in the background without spamming the backend with redundant polling requests.*
- *As a Platform Engineer, I want the backend traffic profile to scale linearly and gently with student cohort size, operating safely within Railway Hobby and Supabase Free tier quotas.*

### Functional Requirements

- [ ] **FR-01 (Eliminate Polling in Student Live Inspection):**
  - Delete `LIVE_INSPECTION_RECONCILE_INTERVAL_MS` (500ms) and `scheduleReconcile` from [`packages/hooks/src/live-inspection/use-student-live-inspection-publisher.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/live-inspection/use-student-live-inspection-publisher.ts).
  - Ensure student publisher triggers `reconcile` strictly on:
    1. Supabase Realtime broadcast event (`LIVE_INSPECTION_CHANGED` on topic `exam-attempt:${attemptId}:live-inspection`),
    2. Channel subscription event (`SUBSCRIBED`),
    3. Document `visibilitychange` (tab re-focus),
    4. Window `online` (network reconnect).
- [ ] **FR-02 (Eliminate Redundant Active Attempt Session Status Polling):**
  - In [`packages/hooks/src/query/exams/use-exam-session-status-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-session-status-query.ts), remove aggressive 2,000ms polling (`refetchInterval: false`).
  - Terminal states (LOCKED, CLOSED, SUBMITTED) are naturally communicated via:
    1. Direct 409 conflict returned by `syncExamProgress` during 2s debounced answer syncs or 30s heartbeats,
    2. Explicit termination upon turn-in completion.
- [ ] **FR-03 (Tame Student Lobby Polling):**
  - In [`use-exam-lobby-admission-status-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-lobby-admission-status-query.ts) and [`use-exam-lobby-count-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-lobby-count-query.ts), disable continuous background polling, relying on `useLobbyRealtime` for instant WebSocket cache invalidation.
- [ ] **FR-04 (Optimize Instructor Dashboard Query Intervals):**
  - In [`use-exam-monitoring-overview-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-monitoring-overview-query.ts) and [`use-exam-incidents-query.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/query/exams/use-exam-incidents-query.ts), relax polling interval from 2,000ms to 6,000ms–8,000ms and disable background refetching when the instructor tab is blurred.
- [ ] **FR-05 (Explicit Instructor Broadcast Signaling):**
  - Ensure [`packages/hooks/src/live-inspection/use-live-inspection-viewer.ts`](file:///Applications/XAMPP/xamppfiles/htdocs/sentinel/packages/hooks/src/live-inspection/use-live-inspection-viewer.ts) (or API layer) dispatches the `LIVE_INSPECTION_CHANGED` broadcast event immediately when `start()` or `stop()` is called so the student wakes up in real-time.
- [ ] **FR-06 (Database Connection & Supavisor Pooler Configuration):**
  - In `packages/db/src/db.ts`, update default `DB_POOL_MAX` to `15`.
  - Configure Railway `DATABASE_URL` to use the Supabase Supavisor Transaction Pooler (port `6543`) with `?pgbouncer=true` or pooler host connection.
- [ ] **FR-07 (Railway 2-Replica Load Balancing):**
  - Deploy `sentinel-api` on Railway with `2` replicas for active-active edge load balancing.

## 4. Resolved Decisions Ledger

| # | Topic | Selected Option | Rationale |
|---|---|---|---|
| **D1** | Target Concurrency Scale | **50–150 Concurrent Students** | Testing phase target. Eliminates all bottlenecks while staying 100% within Railway Hobby ($5 credit) and Supabase Free tiers. |
| **D2** | Live Inspection Wake-up Architecture | **100% Realtime Event-Driven Signaling** | Strips out the 500ms HTTP polling loop completely. Drops student background traffic to **0 req/sec**. Wakes up strictly via Supabase Realtime WebSocket broadcast + reconnect triggers. |
| **D3** | Railway & Supabase Load Balancing | **2 Railway Replicas + Supavisor Transaction Pooler (Port 6543)** | Multiplexes database queries through port 6543 with `DB_POOL_MAX=15`, eliminating connection limits and providing redundant high availability on Railway. |
| **D4** | Monorepo Polling Cleanup | **De-duplicate all 5 discovered Polling Leaks** | Eliminates redundant `refetchInterval` in session status and lobbies, and relaxes monitoring queries to 6–8s. |

## 6. Scope & Boundaries

- **In Scope:**
  - Removal of `LIVE_INSPECTION_RECONCILE_INTERVAL_MS` (500ms) in `useStudentLiveInspectionPublisher`.
  - Removal of redundant `EXAM_SESSION_STATUS_REFETCH_INTERVAL_MS` in `useExamSessionStatusQuery`.
  - Elimination/taming of redundant polling in student lobby hooks.
  - Relaxing monitoring overview and incident polling to 6s.
  - Adding explicit Realtime broadcast emission in `useLiveInspectionViewer` and/or backend start/stop services.
  - Database pool tuning in `packages/db` (`DB_POOL_MAX=15`) and documentation for Railway 2-replica & Supavisor port 6543 setup.
  - Updating all relevant Vitest test suites.

- **Out of Scope / Non-Goals:**
  - Upgrading to paid Railway Pro plan ($20/mo) at this time (deferred until 300+ students).
  - Changing MediaPipe or Audio anomaly detection ML algorithms.
  - Modifying exam grading or question builder data structures.
